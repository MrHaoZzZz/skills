# C++ 高级 · 并发与多线程

并发（concurrency）是提升性能、充分利用多核 CPU 的关键，也是 C++ 中较难的部分。C++11 起标准库提供线程支持。

## 1. 基本线程

```cpp
#include <thread>
#include <iostream>

void hello() {
    std::cout << "hello from thread\n";
}

int main() {
    std::thread t(hello);   // 创建线程，立即开始执行
    t.join();               // 等待线程结束（必须 join 或 detach）
    return 0;
}
```

**关键规则**：`std::thread` 销毁前必须 `join()`（等待）或 `detach()`（分离），否则 `std::terminate`。

## 2. 数据竞争（data race）

多个线程同时读写同一数据且不加保护 → **未定义行为**，是最危险的并发 bug。

```cpp
int counter = 0;

void increment() {
    for (int i = 0; i < 100000; ++i)
        ++counter;    // 危险！多线程下不是原子操作
}
```

`++counter` 实际是「读-改-写」三步，线程会互相覆盖，结果不确定。

## 3. 互斥锁（mutex）

```cpp
#include <mutex>

std::mutex mtx;
int counter = 0;

void increment() {
    for (int i = 0; i < 100000; ++i) {
        std::lock_guard<std::mutex> lock(mtx);  // RAII 自动加锁解锁
        ++counter;
    }
}
```

- `std::mutex`：互斥锁，保证同一时刻只有一个线程进入临界区。
- `std::lock_guard`：RAII 包装，离开作用域自动解锁（推荐，别手动 lock/unlock）。
- `std::unique_lock`：更灵活，可延迟加锁、转移所有权。

## 4. 原子操作（atomic）

无需锁也能安全读写单个值。

```cpp
#include <atomic>

std::atomic<int> counter{0};

void increment() {
    for (int i = 0; i < 100000; ++i)
        ++counter;   // 原子操作，无需锁
}
```

`std::atomic` 比 mutex 轻量，但只适合简单操作；复杂逻辑仍需锁。

## 5. 条件变量（condition_variable）

用于线程间「等待某条件成立」，配合 mutex 使用。

```cpp
#include <condition_variable>

std::mutex m;
std::condition_variable cv;
bool ready = false;

// 生产者
{
    std::lock_guard<std::mutex> lock(m);
    ready = true;
}
cv.notify_one();   // 唤醒一个等待线程

// 消费者
std::unique_lock<std::mutex> lock(m);
cv.wait(lock, [] { return ready; });   // 等到 ready 为 true
```

**要点**：`wait` 的第二个参数是谓词，用于防止虚假唤醒（spurious wakeup）。

## 6. 异步与 Future

```cpp
#include <future>

int compute() { return 42; }

std::future<int> f = std::async(std::launch::async, compute);
int result = f.get();   // 阻塞等待结果
```

`std::async`/`std::future` 是比裸线程更高层的抽象，适合「执行任务拿结果」的场景。

## 7. 死锁（deadlock）与预防

两个线程互相等待对方释放资源 → 死锁。

预防法则：
1. **固定加锁顺序**：所有线程按相同顺序加多把锁。
2. **用 `std::lock` / `std::scoped_lock` 一次锁多把**：

```cpp
std::scoped_lock lock(m1, m2);   // C++17，原子地锁住多把，避免死锁
```

3. 尽量缩小临界区、避免在持锁时调用外部代码。

## 8. 内存模型与 happens-before

C++ 内存模型定义了「哪些操作对哪些线程可见」。规则：

- 同一线程内，前面的操作 happens-before 后面的操作。
- 解锁 happens-before 之后的加锁。
- 原子操作配合内存序（memory order）提供同步保证。

初学阶段记住：**默认的原子操作（`memory_order_seq_cst`）最安全**，别乱用 relaxed 内存序，除非你明确理解其代价。
