# C++ 算法与竞赛思维

本章面向「有算法竞赛背景（OI/ACM）但生疏」或「热爱极致算法思考」的学习者。核心目标：用 C++ 把「算法正确性」和「复杂度」推到极致。

## 1. 复杂度分析（Big O）

一切算法讨论的前提。牢记常见量级与对应数据规模（1 秒约 1e8 次简单运算）：

| 复杂度 | 常见算法 | 可处理规模 n |
|--------|----------|-------------|
| O(log n) | 二分、平衡树 | 任意 |
| O(n) | 线性扫描、双指针 | 1e7 ~ 1e8 |
| O(n log n) | 排序、堆、分治 | 1e5 ~ 1e6 |
| O(n²) | 简单 DP、双重循环 | 1e3 ~ 1e4 |
| O(n³) | Floyd、三重循环 | 100 ~ 500 |
| O(2ⁿ) | 枚举子集、暴力 | 20 ~ 25 |

**分析口诀**：数「基本操作执行次数」随 n 的增长级，忽略常数和低阶项。

## 2. 常用算法清单（按竞赛频率）

- **排序与二分**：`sort`、`stable_sort`、`lower_bound`/`upper_bound`/`binary_search`。
- **搜索**：DFS（回溯）、BFS（最短路）、剪枝。
- **贪心**：区间调度、哈夫曼。
- **动态规划**：背包、最长上升子序列、区间 DP、状压 DP。
- **图论**：最短路（Dijkstra/Floyd/Bellman-Ford）、最小生成树（Kruskal/Prim）、拓扑排序、连通分量。
- **数据结构**：并查集、线段树/树状数组、ST 表、单调栈/队列、堆。
- **字符串**：KMP、Trie、哈希。
- **数学**：素数筛、快速幂、逆元、组合数、gcd/exgcd。

## 3. STL 在竞赛中的高频用法

```cpp
#include <bits/stdc++.h>   // 竞赛万能头（工程中勿用，编译慢、非标准）
using namespace std;

// 排序 + 自定义比较
sort(a.begin(), a.end(), greater<int>());   // 降序
sort(v.begin(), v.end(), [](int x, int y) { return abs(x) < abs(y); });

// 二分：返回「第一个 >= x」的迭代器
auto it = lower_bound(v.begin(), v.end(), x);
int idx = it - v.begin();                   // 转下标
// upper_bound：第一个 > x

// 优先队列（堆）：默认大顶堆
priority_queue<int> pq;                     // 大顶堆
priority_queue<int, vector<int>, greater<int>> minHeap;  // 小顶堆

// 平衡树 / 哈希表
set<int> s;                                 // 有序去重
map<int, int> mp;                           // 有序键值
unordered_map<int, int> ump;                // O(1) 均摊，无序
multiset<int> ms;                           // 可重复有序（可作懒删除堆）

// 排列
next_permutation(v.begin(), v.end());

// 双端队列
deque<int> dq;

// 字符串常用
string s = "abc";
s.find("bc");        // 返回下标或 string::npos
s.substr(1, 2);      // 子串
to_string(123);      // 数字转字符串
stoi("123");         // 字符串转 int
```

## 4. 性能与常数优化

### 内存与缓存局部性

- 二维数组按「行优先」遍历（`a[i][j]` 连续），比按列遍历快得多。
- 频繁访问的小对象放连续内存（数组/vector），利于缓存。

## 5. 竞赛码风 vs 工程码风（转型核心）

| 维度 | 竞赛码风（可以） | 工程码风（应该） |
|------|------------------|------------------|
| 万能头 | `#include <bits/stdc++.h>` | 只包含需要的头文件 |
| 命名空间 | `using namespace std;` | 用 `std::` 前缀 |
| 宏 | `#define int long long` | 避免宏，用 `using`/`constexpr` |
| 变量名 | `dp`、`a`、`n`、`m` | 有意义的命名（如 `maxProfit`、`customerCount`） |
| 全局状态 | 大量全局数组/变量 | 封装进类/函数，传参或依赖注入 |
| 函数拆分 | 全塞进 `main`，几百行 | 单一职责，每个函数 < 50 行 |
| 错误处理 | 假设输入合法 | 校验输入、异常处理、防御性编程 |
| 内存 | 静态大数组，不关心泄漏 | RAII、智能指针、容器 |
| const 正确性 | 几乎不用 | 该 const 就 const |
| 测试 | 手测/对拍 | 单元测试、自动化测试 |
| 注释与文档 | 几乎不写 | 关键逻辑写注释，接口写说明 |

### 同一道题的两种写法对比

```cpp
// ❌ 竞赛写法：快，但工程上不可维护
#include <bits/stdc++.h>
using namespace std;
#define int long long
int a[100005], n;
signed main() {
    scanf("%d", &n);
    for (int i = 0; i < n; i++) scanf("%d", &a[i]);
    int ans = 0;
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
            ans += max(a[i], a[j]);
    printf("%d\n", ans);
}
```

```cpp
// ✅ 工程写法：同样正确，但清晰、可测试、可维护
#include <algorithm>
#include <cstdint>
#include <iostream>
#include <vector>

// 计算所有无序对 (i<j) 中较大值之和
std::int64_t sumOfPairMax(const std::vector<int>& values) {
    std::int64_t total = 0;
    const std::size_t n = values.size();
    for (std::size_t i = 0; i < n; ++i) {
        for (std::size_t j = i + 1; j < n; ++j) {
            total += std::max(values[i], values[j]);
        }
    }
    return total;
}

int main() {
    std::size_t n;
    if (!(std::cin >> n)) {
        std::cerr << "Invalid input\n";
        return 1;
    }
    std::vector<int> values(n);
    for (auto& v : values) {
        if (!(std::cin >> v)) {
            std::cerr << "Invalid input\n";
            return 1;
        }
    }
    std::cout << sumOfPairMax(values) << '\n';
    return 0;
}
```

### 转型行动清单

按这个顺序逐步改掉竞赛习惯（每个都能立刻上手）：

1. **去掉万能头和 `using namespace std`**，改成显式 `std::` 前缀 + 按需包含。
2. **删掉宏**（尤其 `#define int long long`），用 `std::int64_t`/`using`/`constexpr`。
3. **消灭全局数组**：`main` 里创建容器，通过函数参数传递（引用传递避免拷贝）。
4. **拆分函数**：每个函数只做一件事，命名「动词+名词」（`readInput`、`computeAnswer`、`printResult`）。
5. **加 const**：不修改的参数标 `const&`；不修改成员的方法标 `const`。
6. **改用 RAII**：`new`/`delete` → `std::vector`/`std::string`/智能指针。
7. **加输入校验**：检查 `cin` 失败、数组越界、除零。
8. **开始写测试**：哪怕只是简单断言，验证边界和典型输入。

**关键认知**：竞赛追求「最短时间内写对 + 跑得够快」，工程追求「可维护 + 安全 + 团队协作」。你的算法底子（复杂度直觉、数据结构选型、边界处理）是工程中非常稀缺的能力，**千万别丢**；要补的是工程规范、抽象能力、测试意识。转型不是否定过去，而是在强算法地基上加盖工程大厦。
