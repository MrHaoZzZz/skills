# C++ 进阶 · 指针、引用与内存管理

这是 C++ 与大多数高级语言**最根本的区别**所在。掌握这一章，才算真正「入门 C++」。

## 1. 内存模型

程序运行时，内存大致分几个区：

| 区域 | 存放内容 | 生命周期 |
|------|----------|----------|
| **栈（stack）** | 局部变量、函数参数 | 函数返回即自动释放 |
| **堆（heap）** | 动态分配的对象 | 手动释放（或用 RAII 自动） |
| **静态区** | 全局变量、`static` 变量 | 程序全程 |
| **代码区** | 编译后的指令 | 程序全程 |

类比：栈像一摞盘子（后进先出，自动收走），堆像仓库（空间大、自由，但要自己记账管理）。

## 2. 指针（pointer）

**指针是「存地址的变量」**。它不存值本身，而是存某个内存地址。

```cpp
int  x = 42;       // x 存在某地址，值为 42
int* p = &x;       // &x 取 x 的地址，p 存这个地址

std::cout << x  << '\n';  // 42（值）
std::cout << &x << '\n';  // 地址，如 0x7ffee...
std::cout << p  << '\n';  // 同样的地址
std::cout << *p << '\n';  // 42（*p 解引用：取 p 指向的值）
```

三个关键运算符：
- `&x`：取地址（address-of）
- `*p`：解引用（dereference），读取/修改 p 指向的值
- `*` 在类型里：声明指针 `int* p;`

```cpp
*p = 100;          // 通过指针修改 x，x 现在等于 100
```

### 指针的用途
1. **共享修改**：多个函数/对象通过指针操作同一份数据（避免拷贝）。
2. **动态分配**：在堆上创建对象，大小运行时才知道。
3. **构建数据结构**：链表、树等。

### 空指针与野指针

```cpp
int* p = nullptr;        // 空指针（现代 C++ 用 nullptr，不用 NULL 或 0）
// 野指针：指向已释放或未初始化内存的指针 —— 危险，会导致未定义行为(UB)
```

**易错点**：解引用空指针/野指针 → 崩溃或未定义行为（undefined behavior, UB）。解引用前务必判断。

## 3. 引用（reference）

**引用是「变量的别名」**，不占额外存储（通常实现为指针，但语义上是别名）。

```cpp
int x = 10;
int& r = x;    // r 是 x 的别名，不是副本
r = 20;        // x 也变成 20

// 引用必须初始化，且不能改变绑定
// int& r2;    // 错误：引用必须初始化
```

### 引用 vs 指针

| 特性 | 指针 | 引用 |
|------|------|------|
| 可为空 | 是（nullptr） | 否 |
| 可重新指向 | 是 | 否（绑定即固定） |
| 语法 | 需 `*` 解引用 | 直接当变量用 |
| 用途 | 需要「可能为空/可变指向」 | 函数参数、返回（推荐） |

**惯用法**：函数参数优先用引用（避免拷贝、语义清晰），需要「可能为空」时才用指针。

## 4. 动态内存：new / delete

```cpp
int* p = new int;        // 堆上分配一个 int，返回地址
*p = 5;
delete p;                 // 释放！否则内存泄漏（memory leak）

int* arr = new int[10];   // 分配数组
delete[] arr;             // 数组用 delete[]
```

**核心规则**：`new` 和 `delete` 必须成对，`new[]` 配 `delete[]`。

**陷阱**：
- 忘记 `delete` → 内存泄漏
- 重复 `delete` → 双重释放（double free），崩溃
- 用 `delete` 释放 `new[]` 的数组 → UB

> **这就是 C++ 最大的坑，也是 RAII（下一节）存在的理由。**

## 5. RAII（资源获取即初始化）

RAII = **Resource Acquisition Is Initialization**。核心思想：**把资源（内存、文件、锁）的生命周期绑定到对象的生命周期**——对象构造时获取资源，析构时自动释放。这样即使发生异常或提前返回，资源也不会泄漏。

```cpp
#include <memory>

void f() {
    // 智能指针：离开作用域自动 delete，无需手动释放
    std::unique_ptr<int> p = std::make_unique<int>(42);
    // 即使这里抛出异常，p 析构时也会自动释放
}   // p 离开作用域，自动 delete
```

**现代 C++ 铁律**：**不要手动 `new`/`delete`**，用智能指针和容器管理资源。这能消除 90% 的内存 bug。

## 6. 生命周期与悬垂引用

```cpp
int* bad() {
    int x = 5;
    return &x;    // 错误！x 在函数返回后销毁，返回悬垂指针(dangling pointer)
}

int& alsoBad() {
    int x = 5;
    return x;     // 错误！悬垂引用(dangling reference)
}
```

**规则**：绝不返回指向局部变量的指针或引用。
